# LC (Limit Checker) actionpoint/watchpoint result vectors are 177-element
# arrays of single-value states (STALE / NOT_USED_STALE) -- runtime status, not
# health signals. Each element is zero-variance (cardinality 1) so it slips
# under the cardinality cap, yet one-hots into a constant column + an "_Other"
# bucket that trips on any change -> ~706 junk features. Deny the base names;
# the array-index stripping in is_excluded() drops all _0.._176 elements.
APRESULTS	# DROP: LC actionpoint result array (per-element single-value state)  (LC)
WPRESULTS	# DROP: LC watchpoint result array (per-element single-value state)  (LC)

# SCH (Scheduler) timing internals: vary with runtime timing, not health/security.
# Both were the only SCH numerics to survive the zero-variance drop, and both
# drive false positives. Denying them empties SCH's autoencoder (its integrity
# STATE fields -- SYNCTOMET, MAJORFRAMESOURCE, IGNOREMAJORFRAME -- are covered by
# exact-match rules instead).
LASTSYNCMETSLOT	# DROP: cyclic MET slot pointer (0..99); capture caught only endpoints -> FPs on any mid-cycle slot  (SCH)
UNEXPECTEDMAJORFRAME	# DROP from AE: cumulative anomaly counter -> FPs on increment. NOTE: security-relevant; wants a "stays at 0, alert on increment" rule, not silent loss  (SCH)
